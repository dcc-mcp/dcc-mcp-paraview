# ParaView pipeline

Work in the adapter-owned isolated pvpython session. Inspect first, use unique source names, and keep files inside the configured workspace. Existing GUI sessions are unaffected.

Start each async operation once. Follow the returned Core job id with jobs_get_status until terminal. A timeout is not permission to replay a mutation. Query the existing job; a native host timeout or cancellation closes this isolated session and discards unsaved pipeline state.

Native PVSM files may reopen only if unchanged and saved by this running session. Arbitrary external states are rejected because they can contain executable filters. VTI/VTU/VTP datasets can be opened across sessions. Exports never overwrite. Sphere/polydata exports use .vtp; clips/unstructured grids use .vtu.

render_preview requires a working DISPLAY. The adapter returns render_unavailable before touching rendering when DISPLAY is absent. A defined but unusable display may still crash the owned native host; no rendering success is implied by capability detection.

For scalar volumes, open a single-file VTI and inspect point_arrays; contour takes a scalar and at most eight values. render_preview accepts scalar, fixed color_range, a named preset, camera_position, camera_target and background; its view remains in subsequent native saved states.


The candidate runtime is Linux with ParaView 5.13.2 and exact Core/server 0.20.41 pins. Startup rejects other host/Core versions before admitting work. Use Python 3.10–3.12 for the sidecar. Historical native acceptance used Core/server 0.20.39 and Python 3.12.14; this upgrade has not inherited it. `get_adapter_info` labels the current profile as an upgrade candidate with `native_qualified=false`.

All symlink path components, including aliases within the workspace and dangling links, are rejected. Camera position and target must differ; color_range requires scalar. PNG success includes native image decoding, nonflat pixel ranges, camera/background/representation readback and scalar transfer-function readback. A present DISPLAY alone is not successful rendering evidence.

Core async cancellation is available through the instance REST DELETE /v1/jobs/{job_id} route. Historical Core 0.20.39 exposed no jobs_cancel MCP tool; reconfirm discovery and cancellation on the candidate before native qualification. Cancellation terminates the owned host; inspect the existing job and start a new adapter instance if you need a fresh pipeline. A stopped server/session object is never restartable.


## Bounded material and framing controls

`render_preview` supports `solid_color` RGB in [0,1] (mutually exclusive with
`scalar`), `show_scalar_bar` and `show_orientation_axes` booleans, an explicit
nonzero `camera_view_up`, and `camera_view_angle` in [1,120] degrees.
`camera_parallel_scale` in [0.001,1000000] enables orthographic projection and
sets its half-height; omitting it chooses perspective projection. `ambient`,
`diffuse` and `specular` are coefficients in [0,1]; `specular_power` is [1,128].
These are native ParaView properties, read back after rendering. All views still
show one bounded Surface source. No stream tracer, tube, layer compositing or
camera animation tool is exposed. Hiding a legend does not change scalar data or
the fixed color range; scientific views should retain an explicit visible scale
or convey that scale in the surrounding figure caption.

## Portable native state

For a movable public project, copy the unchanged input files into an existing
`data` subdirectory beside the intended new PVSM, then call `save_state` with
`path` and `data_directory`. The adapter checks each copied file's saved-input
SHA256, temporarily sets native reader FileName properties to package-relative
paths, calls native SaveState, verifies FileName and FileNameInfo plus absence
of absolute filesystem references, then restores the live original readers.
It does not edit serialized XML and does not copy or overwrite input data.

`reopen_state(path, data_directory=...)` accepts an unchanged relocated copy only
when its hash matches a state generated by this current owned session. It verifies
all copied input digests before resetting the pipeline, calls native LoadState
with exact reader-ID/filename mappings, and reads back the new paths and pipeline.
No fallback to old absolute input locations occurs. A state created in another
session remains untrusted even if it includes a caller-written manifest.

For a downloaded project in ParaView's GUI, use Load State and select the
packaged data directory if prompted. Keep original state, package and validation
hashes. Reproducing the typed recipe in a fresh MCP session is supported; arbitrary
external PVSM import is not. Workspaces and artifact copies must be operator-owned.

## True sections and existing presentation

Use `slice_plane` for a true polygonal plane section of an existing source, with
finite origin and nonzero normal. It preserves point arrays, checks native plane
and input bindings, caps input/output at 1,000,000 points and cells each, and
deletes a failed new slice. It never opens or creates an implicit input. Export
sections as `.vtp`; keep the existing 32-source session limit.

`inspect_presentation` is read-only: it inventories existing views, attached
representations and scalar bars without creating them. Camera, size, material,
background, scalar selection, actual palette/range and legend are returned.
Bindings use stable registered source names, so fresh native proxy IDs after
reopen do not produce false differences. Actual RGB control points are reported;
a preset label is not inferred. Missing camera clipping-range support is reported
in `unavailable_properties`; no implicit camera creation is used to fill it.

After configuring a view or reopening a trusted saved state, call
`inspect_presentation`, then `capture_current_view(path)` to capture the existing
view with no camera, size or visibility changes. Successful capture verifies
unchanged measured presentation and decoded native PNG pixels. If ParaView's
first render resets presentation, the tool returns `presentation_changed`,
publishes no image and leaves the changed state available for inspection. Never
call `render_preview` before that capture to hide a restore mismatch. Five
separately saved viewpoint states are supported; no multi-view authoring tool
is provided. Native qualification for these additions is pending.
