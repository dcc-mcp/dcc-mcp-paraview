# Architecture and trust boundaries

`DccServerBase` and `DccServerOptions.from_env` own MCP transport, discovery, registry and Core job lifecycle. `HostExecutionBridge` is attached before skill discovery. Its `HostUiDispatcherBase` subclass owns one long-lived transport-pump thread and drains Core's Python and native HTTP queues. There is no per-request helper thread, duplicate queue, job registry, inner-server access or runtime parsing of tool manifests.

A main-affinity call reaches a package-owned skill wrapper on the IPC pump. The wrapper sends a bounded JSON frame over private anonymous pipes to one persistent adapter-owned `pvpython`. **Only `host_driver.py` imports ParaView; every API call runs on that process's main thread.** HTTP workers never import or invoke ParaView. The child starts with an empty isolated session, not an existing user's GUI session.

The IPC request carries a random request id and the server-owned Core job id. Responses must match both ids and the exact result/error envelope. Duplicate JSON keys, nonfinite JSON, malformed data, conflicting result/error fields and unexpected envelope keys fail closed. Readiness requires protocol 1 and qualified ParaView 5.13.2; the native reported PID may be namespace-local and differ from the owned launcher PID. Arguments are validated independently in the client and child. The nonblocking write/read transport is bounded by a 60-second deadline and 1 MiB inbound and outbound frames; at most 64 KiB of native startup diagnostics are tolerated only before readiness; native data files by 64 MiB and source count by 32. The host process retains its pipeline between operations.

Core cancellation is checked before admission and while waiting for the child. If it fires, the cancellation signal is forwarded by terminating the owned process. After a timeout, broken pipe, cancellation or mismatched response, the session is closed permanently; there is no automatic restart, stale-response reuse or mutation replay. Tests prove delayed host mutations do not run after termination. This is process termination, not cooperative interruption or rollback of a native API call.

File writes stage a unique sibling output, verify it, and hard-link it to a new final name atomically. Existing files are preserved even if created concurrently before publication. The staging file is removed. Paths are checked lexically before resolution; all symlink components, including in-root aliases and dangling links, and parent traversal are rejected. A trusted workspace is required; this is not a hardened OS filesystem sandbox.

Only single-file XML VTK readers are allowed. XML entity/DTD declarations, external file references and extension/type mismatches fail closed. Imported native parsers still belong to ParaView's security boundary. Native state is never accepted from an arbitrary caller: an in-memory allowlist records each saved path, digest and source snapshot; reopen checks that exact artifact before resetting the isolated session and calling native LoadState. The loaded pipeline is then compared with the saved snapshot.

Mutations return Core `skill_success` with verified readback; expected errors use a string `skill_error` code. Domain result fields are separate from the outer IPC transport's result/error fields. Render views, once successfully created, remain available in subsequent PVSM exports. Rendering checks the native representation enum, camera position/target/up vector, background, image size, scalar selection and transfer-function range/control points. The PNG is decoded with the native reader and must have the requested dimensions and nonflat RGB pixels. Successful display-backed acceptance is tracked separately in validation evidence.


The request serialization lock is separate from the shutdown lock. Stop can terminate an active host immediately rather than waiting behind a monolithic request. Owned process-group descendants are terminated even if their launcher has exited; no completion or rollback is inferred from termination. Stopping is idempotent; restarting requires a fresh server/session object. Construction/start failures close host resources and the Core pump. Direct queued or active Python-dispatch timeouts call Core's public cancel API before returning so later queue draining cannot execute abandoned work.
